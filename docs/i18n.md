# 语言文件说明（i18n）

本项目有两套互不重叠的语言表：

| 目录 | 加载方 | 用途 |
|---|---|---|
| `src/main/resources/assets/bbs_together/assets/strings/<lang>.json` | BBS 的 `L10n`（`BBSTogetherClient.onRegisterL10n`） | **所有客户端 UI**：BBS 仪表盘 / 编辑器界面、合作录制的菜单·邀请·房间·弹窗、资产锁选择器 |
| `src/client/resources/assets/bbs_together/lang/<lang>.json` | Minecraft 原版语言表 | **仅服务器下发的消息**：`Text.translatable(...)`（命令、诊断、分支、提交、锁定、上传、合作录制结果通知等） |

## 跟随 BBS 的语言切换

- 客户端 UI 的键全部在 `strings/`，由 BBS 的 `L10n` 解析。BBS 在设置里切语言时，这些文案（包括合作录制菜单里的「请求合作录制」）会一起切换。
- `CoopL10n.key(...)` 现在只是 `L10n.lang(...)` 的薄封装，不再走原版语言表。
- 服务器消息仍在 `lang/`，因为服务器发给客户端的是原版 `Text.translatable` 组件，由客户端按 **Minecraft 语言**（`options.txt` 的 `lang:`）解析。服务器无法替客户端解析 BBS 的 `L10n`；若要让服务器消息也跟随 BBS 语言，需要把消息改成自定义包、由客户端用 `L10n` 渲染（目前未做）。
- 因此：**BBS 设置的语言与原版语言不一致时，客户端 UI 跟随 BBS，服务器消息跟随原版**。把两者设成同一种语言即可完全一致。

## 回退规则

- BBS 的 `L10n.reload()` 总是**先加载 `en_us`**，再用当前语言覆盖；因此目标语言缺少的键会自动回退到英文。
- 原版 `lang/` 同样以 `en_us` 为默认语言回退。
- 所以 `en_us` 必须是完整、唯一的“源表”。

## 文件维护约定

- `en_us`：保留全量键，代码里用到的每个静态键都必须在这里。
- `zh_cn`：同样保留全量，保证中文不依赖英文回退。
- 其它语言（`de_de`、`fr_fr`、`zh_tw`……）：**只保留与 `en_us` 不同的条目**。缺的键会自动显示英文；不要把英文原文再抄进这些文件，否则英文文案更新后会留下过期副本。新增语言时只写真正翻译过的条目即可。
- 动态拼接的键必须补齐所有后缀（都写在 `en_us` 里）：
  - `bbs_together.bbsop.domain.*`（`BbsOpDomain` 的 `id`）
  - `bbs_together.bbsop.level.*` / `bbs_together.bbsop.group.*`（0/1/2）
  - `bbs_together.behaviors.type.*`（`BehaviorType` 名称小写）
  - `bbs_together.behaviors.status.*`（`pending` / `approved` / `denied`）
  - `bbs_together.lock.noun.*`（`film` / `model` / `model_block`）
  - `bbs_together.config.<category>.<id>` 与 `-comment`：由 BBS 的 `UIValueFactory` 根据设置项路径自动生成，必须与 `TogetherSettings` 里的 category / id 一致。
- 已删除的死键（不要再加回来）：`bbs_together.bbsop.query`、`bbs_together.bbsop.set`、`bbs_together.notification.synced`。服务器端的 `/bbsop` 反馈使用 `bbs_together.command.bbsop.*`（位于 `lang/`）。

## 新增一条文案

1. **客户端 UI**（按钮、标题、菜单、弹窗、选择器）：在 `strings/en_us.json` 与 `strings/zh_cn.json` 各加一条，代码里用 `L10n.lang("键")`；合作录制 / 资产锁的 UI 继续用 `CoopL10n.key("键")`（它等价于 `L10n.lang`）。
2. **服务器消息**（命令反馈、聊天通知）：在 `lang/en_us.json` 与 `lang/zh_cn.json` 各加一条，代码里用 `Text.translatable("键", 参数...)`。
3. 其它语言只在确实翻译后追加，且只写与英文不同的条目。

## 校验

- 所有 `src/**/*.json` 必须可解析，且无重复键。
- `en_us` 与 `zh_cn` 的键集合必须完全一致。
- 其它语言的键必须是 `en_us` 的子集。
- `%s` / `%d` 与 `{placeholder}` 在 `en_us`、`zh_cn` 中必须一一对应。
- `CoopL10n.key(...)` / `L10n.lang(...)` 的静态键必须能在 `strings/en_us.json` 找到；`Text.translatable(...)` 的静态键必须能在 `lang/en_us.json` 找到。
