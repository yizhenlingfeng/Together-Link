# 多人分支隔离 · 实施记录

## 1. 需求

同一部影片允许多名玩家分别处于不同分支：

- 每名玩家有自己的“当前分支”，切分支只影响自己；
- 每个分支有独立的影片工作副本，不同分支的未提交改动互不覆盖；
- 同一分支的玩家仍保持现有实时协作（光标、选中、数据同步、完整保存）；
- 分支选择与分支工作副本跨服务器重启保留；
- 提交只落到发起者当前分支，服务器接受来自不同分支的提交；
- 主影片文件 `<存档>/bbs/films/<影片>.dat` 继续代表影片的**默认分支**，供影片列表、预览和不带分支概念的功能使用。

## 2. 术语

| 名称 | 含义 |
| --- | --- |
| 默认分支 | `FilmCommitStore.Store.current` 指向的分支；主影片文件与它同步。新玩家默认进入这个分支 |
| 分支工作副本 | 某个分支当前未提交的完整影片数据，独立于其他分支 |
| 玩家分支 | 某名玩家在某部影片上停留的分支，按 `(影片, 玩家)` 持久化 |
| 分支头 | `FilmCommitStore.Store.branches` 中该分支最新提交的 id |

默认分支：

- 旧存档沿用升级前 `index.bin` 里的 `current`，因此主文件内容与默认分支一致；
- 新影片在没有提交时默认 `main`；
- 切换分支、提交、回退都**不再**改 `current`，避免某个玩家把别人的默认视图切走。默认分支目前没有独立的“设为默认”入口，属于已知限制。

## 3. 存储

```text
<存档>/bbs/films/
├─ <影片>.dat                         # 主影片文件 = 默认分支
└─ _commits/<影片>/
   ├─ index.bin                       # 提交、分支头、默认分支、提交颜色
   ├─ s/<提交id>.bin                  # 提交快照
   ├─ d/<提交id>.bin                  # 提交差异
   ├─ players.bin                     # UUID -> 分支（每名玩家在此影片上的分支）
   └─ w/<branch-sha1>.bin             # 该分支的未提交工作副本
```

- 分支名允许 `/` 等字符，所以工作副本文件用分支名的 SHA-1 命名，避免路径穿越与冲突。
- 写工作副本与 `players.bin` 都先写 `.tmp` 再原子替换。
- 工作副本在首次使用时按以下顺序初始化：
  1. 已有 `w/<hash>.bin`：读取它；
  2. 默认分支：读取主影片文件（可能含旧版本留下的未提交改动）；
  3. 其他分支：读取该分支头提交的快照；
  4. 仍无数据：空影片。
- 服务器停止时 `flushPendingFilmSaves` 先按脏标记落盘，再 `FilmBranchStore.saveAll()`；`films`/`_commits` 的删除与重命名同步清理/搬移分支数据。

## 4. 服务端数据流

新增 `commits/FilmBranchStore`：

- `branchOf(filmId, uuid)`：取玩家分支；无记录或分支已不存在时退回默认分支；
- `setBranch(...)`：校验分支存在后写 `players.bin`；
- `working(filmId, branch)`：返回该分支的 `Film` 对象（缓存）；
- `workingData(...)`：序列化为 `MapType`；
- `setWorking(...)` / `save(...)`：完整替换并落盘；
- `defaultBranch(...)` / `isDefault(...)`。

`TogetherServerNetwork` 的改动：

| 路径 | 行为 |
| --- | --- |
| `s_film_data_sync` | 用发送者分支；只把路径包转发给**同一影片、同一分支**的玩家；`replays` 路径应用到该分支的 `Film`，2 秒防抖落盘；默认分支同时写主文件 |
| `s_film_save_sync` | 合并到发送者分支的 `Film`；广播只发给同分支玩家；默认分支同时写主文件；非默认分支不触发影片列表变化 |
| `s_undo_sync` | 校验、转发、应用到发送者分支；只转发给同分支玩家 |
| `s_commit_head` | 返回玩家当前分支头的快照，供“未提交的改动”对比 |
| `s_commit_create` | 忽略客户端附带的 branch 字段，一律使用发送者当前分支；提交后把该分支工作副本更新为提交内容 |
| `s_commit_revert` | 从提交记录找到目标分支，只移动该分支头，重置该分支工作副本；只向该分支玩家广播完整影片 |
| `s_branch_checkout` | 只改发起者的玩家分支；只向他发送该分支完整影片与提交图；不再写主文件/不再广播给所有人 |
| `c_commits` | 每个收件人附带自己的当前分支，客户端用它覆盖图里的 `current` |
| `c_film_saved_sync` | 元数据附带 branch；客户端只接受与自己当前分支一致的完整影片 |
| `c_film_data_sync` | 元数据附带 branch；客户端丢弃其他分支的增量 |
| 光标 / 回放选中 / 表单锁 / 回放交换 | 只发给同一分支的玩家 |
| `s_film_inventory` | 按玩家分支工作副本的 SHA-1 比对，不再拿主文件覆盖非默认分支的本地文件 |
| Fix28 加入请求 | 不再向其他客户端索要快照，直接从服务器分支工作副本回发 |

提交目标：

- 客户端提交按钮显示“提交到 <当前分支>”；
- 服务端只认发送者的当前分支，避免“选中别的分支的提交 → 把本分支内容写进别的分支”的错位。

主文件：

- 只有默认分支的完整保存、提交、回退、录制合并会写 `<影片>.dat`；
- 非默认分支的改动只写 `w/<hash>.bin`，因此影片列表/预览/其他不带分支概念的读取仍然看到默认分支。

## 5. 客户端

- `TogetherClientNetwork` 维护 `filmId -> branch`，来源为 `c_film_saved_sync`、`c_film_data_sync`、`c_commits`；
- 收到非当前分支的增量包直接丢弃；收到完整影片时更新本机分支并把数据应用到编辑器/本地影片；
- `FilmCommitClient.Graph.current` 使用服务端为本人下发的分支；`UICommitGraph.currentCommit` / `headBranch` / `commitBranch` 都读它；
- 提交按钮与“未提交改动”标题跟随当前分支；
- 切分支前用 `TogetherEditSyncQueue.flushNow(...)` 把旧分支尚未发出的编辑先推给服务器，避免切换后迟到的包落到新分支；
- 切分支时清掉旧分支的回放选中、表单锁与本地分支缓存，防止旧索引指向新分支的回放。

## 6. 录制 / 合作录制

- 普通录制按录制者当前分支合并（`BBSTogetherFix18`、`s_master_done`、录制基线快照都按分支落盘）；
- 合作录制要求所有参与者与发起者处于同一分支，否则邀请时直接提示并拒绝；会话期间禁止切分支；
- 合并结果写入会话创建时记录的分支工作副本；默认分支同时更新主文件。

## 7. 已知限制

- 默认分支固定为升级时 `index.bin` 里的 `current`，目前没有“把某分支设为默认”的 UI；主文件/预览始终看默认分支。
- 不支持合并分支、删除分支；删除提交/回退只影响目标分支的头与工作副本。
- 行为日志的条目仍以影片为单位，附加 `branch` 字段；面板暂未按分支筛选。
- 分支工作副本是完整影片，分支很多时磁盘/内存占用按分支数线性增长。
- 代码协议有分支字段，客户端与服务端必须同版本。

## 8. 验收清单

- [ ] 两名玩家分别检出 A/B 分支，互看对方影片内容不变；
- [ ] A 分支的编辑不会出现在 B 分支；同一分支的两名玩家仍实时同步；
- [ ] 双方分别提交到 A/B，两个分支头都前进，提交图同时可见；
- [ ] 重新进服/重启服务器后，两名玩家仍在各自分支，未提交改动仍在；
- [ ] 切分支只影响发起者，主影片文件与预览仍是默认分支；
- [ ] 回退 A 分支的提交不影响 B 分支玩家；
- [ ] 非默认分支保存不会触发其他分支的完整影片覆盖；
- [ ] 合作录制会拒绝不同分支的受邀者；
- [ ] 影片重命名/删除后 `_commits/<影片>`、`players.bin`、`w/` 同步搬移/清理。
