> 范围：本模组（Together Link / `bbs_together`）为 BBS FS 2.7 的影片编辑器新增"类 Git 的编辑提交图"。

> 文案遵守 `BBS_FS_术语表.md`：影片 / 回放 / 面板 / 轨道 / 关键帧 / 撤回 / 首尾「」/ 中英文之间空格 / 省略号 `...`。

## 1. 目标与非目标

**目标**

1. 三个入口：landing 菜单一行、全屏提交图面板、影片编辑器里的「提交」bar。
2. 每个提交节点可展开到：剪辑 → 字段；回放 → 模型 → 关键帧轨道 / 模型属性轨道 / 动作剪辑。
3. 提交可重命名（右键），重命名不改提交 ID、不动图结构。
4. 不修改 BBS FS 源码（全部通过 mixin / 新面板实现）。

**非目标（本期不做）**

- 三路合并、冲突解决 UI。
- 提交签名、跨影片 cherry-pick。
- 逐帧的画面差异预览（只做数据差异 + 缩略图）。

## 2. 数据模型

### 2.1 提交（Commit）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 短哈希（7 位显示）。**内容寻址**：快照内容 + 父 id + 作者 + 时间，**消息不参与哈希** |
| `filmId` / `filmName` | string | 所属影片 |
| `parents` | string[] | 0（首提交）/ 1（普通）/ 2（合并） |
| `branch` | string | 所在分支 id |
| `authorUuid` / `authorName` | string | 作者；单人存档为 `local` |
| `time` | long | 提交时间（毫秒） |
| `message` | string | **可变**，右键重命名只改这一项 |
| `kind` | enum | `MANUAL` / `AUTO` / `RECORDING` / `REVERT` / `IMPORT` |
| `stats` | Stats | 摘要：剪辑 / 回放 / 轨道 / 关键帧的增删改计数、时长变化 |
| `diffId` | string | 明细文件名，**懒加载** |

**为什么消息不进哈希**：重命名要能"改字不改图"。ID 只由内容与拓扑决定，重命名后节点位置、分支、父子关系、他人引用全部不变，只需广播一个 `s_commit_renamed`。

### 2.2 分支（Branch）

`<filmId, name, color, headCommitId, createdFrom, locked>`。一个影片默认一条 `主线`；从任意节点可派生分支；HEAD 跟随该分支最后一次提交。

### 2.3 变更明细（CommitDiff）

```text
CommitDiff
├─ film:      FieldDiff[]              // 影片级标量
├─ camera:    ClipDiff[]               // 相机剪辑
├─ replays:   ReplayDiff[]             // 回放（= 模型实例）
├─ markers:   MarkerDiff[]             // 时间线标记
└─ categories: CategoryDiff[]          // 回放分组
```

**身份键（最容易踩坑的地方，必须先定）**

| 对象 | 有无稳定 id | 匹配规则 |
| --- | --- | --- |
| 回放 | 有（`Replays extends ValueStableList<Replay>`） | 直接用稳定 id，`Replays.getById(String)` |
| 关键帧轨道 | 有（通道 id / `TrackId.toKey()`） | 直接用字符串键 |
| **剪辑** | **没有**（`Clips` 内部就是 `List<Clip>`，`Clip` 是 `ValueGroup` 且无 id） | 三级匹配，见 §7.2 |
| 模型 | 有（`Form.getId()`） | 直接比较 |

`Clips` 没有稳定 id 这件事决定了：剪辑 diff 不能按下标比，否则"把一个剪辑往前挪 10 tick"会显示成"删了一个 + 加了一个"。这是本计划里最需要专门写测试的地方。

## 3. 明细要显示什么

### 3.1 层级树（右栏）

```text
a1b2c3d  ╭ 主线 ╮ ╭ HEAD ╮                      12:03 · 张三
─────────────────────────────────────────────────────────────
▾ 相机剪辑  2 个改动
   ~ 「推镜 1」 KeyframeClip   层 0   120 - 240
       关键帧 4 → 6 (+2)    时长 120 → 240    不透明度 100 → 80
   + 「淡入」 ImageClip       层 1   300 - 360
▾ 回放  1 个改动
   ~ 「守卫 A」  模型 character/guard   （未换模型）
       ▾ 关键帧轨道  3 条
          位置 X / Y / Z    关键帧 +12    120 - 260
          旋转 偏航          关键帧 3 → 5   80 - 200
       ▾ 模型属性轨道  2 条
          骨骼 head 旋转     关键帧 +4     120 - 260
          IK 目标 hand_r     关键帧 +2     180 - 220
       ▸ 动作剪辑  1 个改动
▸ 标记  1 个改动
▸ 影片属性  2 个改动
```

规则：

- 只展开**有改动**的层；未改动的层整层不显示。
- 删除项用删除线 + 灰字；新增项 `+` 绿；修改 `~` 黄；重命名回放/剪辑用 `→`。
- 每条轨道一行：`名字 · 关键帧增删改 · tick 范围`；点开才显示逐关键帧 diff（最多前 5 条，其余"展开全部"）。
- 顶部一行统计：`3 个剪辑 · 5 条关键帧轨道 · 2 条模型属性轨道 · +128 关键帧 · 时长 +7 秒`。

### 3.2 每一层的字段来源

| 层 | 显示内容 | 数据来源 |
| --- | --- | --- |
| 影片属性 | `description`、`hp`、`hunger`、`xp_level`、`created_at`、`time_spent_active` 的旧值 → 新值 | `Film` 字段 |
| 相机剪辑 | 类型（Idle / Path / Dolly / Keyframe / Image / Video / Subtitle / Audio / Curve，及 11 种修饰器）、`title`、`layer`、`tick` 起止、字段级差异 | `camera\clips\**`，`Clip.title/layer/tick/duration/envelope` |
| 回放 | `label`、模型 `form` id 与显示名、`enabled`、`fp`、`actor`、`looping`、`category` | `Replay` 字段、`Replay.getName()` |
| 回放关键帧轨道 | 通道（位置 / 旋转 / 状态 / 快捷栏 / 装备 / 摇杆 / 扳机 / 额外 / 速度 / 受伤 / 倾角 / 翻滚）的关键帧增删改 + tick 范围 | `ReplayKeyframes` 的各 `KeyframeChannel` |
| 模型属性轨道 | `TrackId.label()` + `formPath`（身体部件路径）+ 关键帧变化；按骨骼 / 约束 / 材质贴图 / 材质属性 / IK 目标 / pole / 物理 / IK 控制 / 物理控制 / 风 分组 | `Replay.properties.tracks`（`Map<TrackId, KeyframeChannel>`）、`TrackId.java` |
| 动作剪辑 | 动作类型、时间范围、目标 | `Replay.actions`（`Clips`） |
| 标记 / 回放分组 | 增删改 | `Film.markers`、`Film.replayCategories` |

### 3.3 通道名映射（按 `ReplayKeyframes.CURATED_CHANNELS` 顺序）

| 通道 id | 显示名 | 分组 |
| --- | --- | --- |
| `x` `y` `z` | 位置 X / Y / Z | 位置 |
| `vX` `vY` `vZ` | 速度 X / Y / Z | 位置 |
| `yaw` `pitch` | 偏航 / 俯仰 | 旋转 |
| `headYaw` `bodyYaw` | 头部朝向 / 身体朝向 | 旋转 |
| `sneaking` `sprinting` `grounded` 等 | 姿态状态（`EntityState` 名） | 状态 |
| `item_slot_0` … `item_slot_8` | 快捷栏 1 … 9 | 物品 |
| `item_off_hand` / `item_head` / `item_chest` / `item_legs` / `item_feet` | 副手 / 头盔 / 胸甲 / 护腿 / 靴子 | 物品 |
| `selected_slot` | 当前快捷栏位 | 物品 |
| `stick_lx` `stick_ly` `stick_rx` `stick_ry` | 左摇杆 X / Y、右摇杆 X / Y | 输入 |
| `trigger_l` `trigger_r` | 左扳机 / 右扳机 | 输入 |
| `extra1_x` `extra1_y` `extra2_x` `extra2_y` | 额外通道 1 / 2 | 输入 |
| `fall` `damage` `leaning` `roll` | 下落距离 / 受伤计时 / 游泳倾角 / 翻滚 | 其他 |

模型属性轨道用 `TrackId.label()` 直接出名字（骨骼 / 材质 / IK 的名字都在里面），`formPath` 非空时前面加上"部件路径"，例如 `0/1 · 骨骼 head`。

### 4.4 重命名提交

```text
┌ 重命名提交 ────────────────────────────┐
│ a1b2c3d · 张三 · 12:03                 │
│ ┌────────────────────────────────────┐ │
│ │ 调了 2 个镜头                       │ │
│ └────────────────────────────────────┘ │
│ 6 / 120                                │
│                      [取消]  [重命名]  │
└────────────────────────────────────────┘
```

- **用对话框而不是就地编辑**：节点行里还挤着 hash、分支胶囊、作者、时间，就地编辑容易点错。
- 校验：去首尾空格后 1 – 120 字符，允许中文；空则「重命名」按钮禁用。
- 权限：作者本人，或 bbsop 2 级；其余人菜单里没有这一项，服务端仍然二次校验。
- 影响：只改 `message`，广播 `s_commit_renamed`，**不产生新提交、不改 ID、不重排图**。
- 审计：行为日志追加一条「重命名了提交 a1b2c3d」，沿用现有 `BehaviorType` + `bbs_together.behaviors.desc.*` 的 key 风格。

## 5. diff 怎么算

1. **触发**：服务端在收到影片保存同步后，按提交策略生成快照。旧快照从提交库取，新快照即当前影片。
2. **比对**：两份都是影片 JSON → `Film.fromData()` → 双树递归走 BaseValue 路径：
   - `camera/<clipIndex>`
   - `replays/<stableId>/keyframes/<channel>`
   - `replays/<stableId>/properties/tracks/<trackId>`
   - `replays/<stableId>/actions/<clipIndex>`
   - `markers/...`、`replay_categories/...`
3. **标量**：`toData()` 相等即无变化，否则记 `old → new`。
4. **关键帧通道**：取 `(tick → value)` 映射，逐 tick 比：旧无新有 = 新增，旧有新无 = 删除，同 tick 值不同 = 修改；顺带记 tick 范围。
5. **剪辑匹配**：见 §7.2。
6. **输出**：只存"有改动的路径"；明细超过 512 KB 时截断并标 `truncated`（右栏显示「明细过大，仅显示前 N 项」）。

## 6. 协议与存储

### 6.1 包

| 包 | 方向 | 载荷 | 用途 |
| --- | --- | --- | --- |
| `c_commits_query` | C→S | filmIds、游标、过滤（分支 / 作者 / 时间） | 拉图 |
| `s_commits` | S→C | 提交元数据列表 + 分支表 + 是否还有更多 | 首次 / 分页 |
| `s_commit_added` | S→C | 单条 Commit | 他人提交实时出现 |
| `c_commit_diff` | C→S | commitId | 按需拉明细 |
| `s_commit_diff` | S→C | CommitDiff | 展开明细树 |
| `c_commit_submit` | C→S | filmId、branch、message、expectedHead | 手动提交 |
| `c_commit_rename` | C→S | commitId、newMessage | 重命名 |
| `s_commit_renamed` | S→C | commitId、newMessage | 广播 |
| `c_commit_revert` | C→S | commitId、expectedHead | 还原 |
| `s_commit_rejected` | S→C | 原因（`HEAD_MISMATCH` / `NO_PERMISSION` / `TOO_LARGE` …） | 拒绝回推 |

`expectedHead` 沿用你们 `s_undo_sync` 那套基线校验：服务端不匹配就拒，提示「李四刚提交了 a1b2c3d」。

### 6.2 存储布局

```text
<world>/bbs/films/
├─ <影片>.json                        # 现有影片文件，不动
├─ _<影片>/<影片>.<时间>.json          # 现有备份，不动（只用来给老存档补种子历史）
└─ _commits/<filmId>/
   ├─ index.json                      # 图元数据：提交、父子、分支、作者、时间、消息、统计
   ├─ d/<commitId>.diff.json          # 明细，懒加载
   └─ s/<commitId>.json               # 快照（完整影片 JSON）
```

- **为什么不能直接复用现有备份**：备份名只到 10 分钟粒度（`yyyy_MM_dd_HH[_m0]`），且写入用 `REPLACE_EXISTING`，同一 10 分钟内多次保存会互相覆盖。拿它当提交，细粒度历史会丢。
- 老存档首次打开提交图：用备份目录生成"历史提交"（`kind = IMPORT`，消息「从备份导入」），再往后才是真提交。
- 清理策略：每分支保留最近 200 条手动提交 + 按天压缩自动提交；`AUTO` 提交超过 30 天按天合并成一条。

## 7. 关键实现约束

### 7.1 剪辑没有稳定 id（`Clips` 内部是 `List<Clip>`）

### 7.2 剪辑匹配三级规则

1. **强匹配**：`(类型, title)` 相同 → 认为是同一个剪辑。
2. **模糊匹配**：`(类型, layer)` 相同且 `tick` 相差 ≤ 2 → 同一个（处理"拖动几帧"）。
3. **顺序匹配**：剩余项按出现顺序做 LCS，配上的算"移动/修改"，配不上的算增删。

匹配结果里"移动"要单独标出来（右栏显示 `→ 从 120 移到 180`），否则用户会以为剪辑被删了。

### 7.3 其他约束

- `Batcher2D` 没有线段/多边形，连线只能用小方块拼。
- `UILandingScreen` 的菜单是局部变量 `rows` 拼出来的，`UIElement.add` 只能追加、没有按索引插入 → landing 那一行只能在对 `UI.column(...)` 的调用点做 mixin 手术。这是全计划**最脆的一环**，BBS FS 升级可能崩，需要单独兜底与测试（备选：dashboard 侧栏图标 + 影片列表右键菜单）。
- 新增 dock 面板要在 `ensure` 里插到 `editArea` 同一 stack，否则老布局会把它甩到别的角落。

## 9. 分步实施

## 15. 改动（撤回 / 回退改为弹窗选择）

### 15.1 行为

| 操作 | 入口 | 回退到 |
| --- | --- | --- |
| 撤回提交 | 页内操作栏「撤回选中提交」、提交图右键「撤回至此提交」 | 该提交的**父提交** |
| 回退到此节点 | 提交图右键「回退到此节点」 | **选中的提交本身** |

两种操作都先弹窗（`UICommitRollbackOverlay`），二选一：

- **删除提交并回退**：被跨过的提交从历史与 `commits/` 目录里删掉，它们的子节点改挂到新的分支头上，图不断裂。
- **保留提交并回退**：只移动分支头，提交留在历史里（对应 `ROLLBACK_KEEP` / `RESET_KEEP`）。

第一个提交没有父提交，所以「撤回」按钮对它禁用并给出提示，右键菜单也不出现该项。

### 15.2 协议与数据层

- `TogetherClientNetwork.sendCommitRevert(String filmId, String commitId, int mode)` 多写一个 mode 字节。
- 模式常量在 `FilmCommitStore`：`ROLLBACK_KEEP = 0`、`ROLLBACK_DELETE = 1`、`RESET_KEEP = 2`、`RESET_DELETE = 3`。
- `FilmCommitStore.rollback(String filmId, String commitId, int mode)` 返回回退后的影片快照（由调用方写进影片文件），并移动 `store.branches` 里的分支头；删除模式下清理提交、重挂子节点；`heldByAnotherBranch` 保证别的分支还指着的提交不会被删。
- 服务端不再生成「撤回至 X」这种新提交，而是移动分支头；广播改为 `broadcastCommits` 全量列表 + `broadcastFilmSaved`。

## 17. 改动（按提交调色、暗灰连线、当前提交高亮）

### 17.1 行为

- **颜色按单个提交**：右键提交（方块节点或文字行）先照常弹出右键菜单——撤回至此提交 / 回退到此节点 / 从此处新建分支 / 提交颜色（短 id）；其中「提交颜色」打开的是 BBS 完整的取色器（`UIColorPicker`：HSV/RGB 滑条、十六进制输入、收藏色与最近色），与 BBS 颜色属性里点色块弹出来的完全是同一个。选中颜色只改这一条提交的方块，立即重绘。右键本身不被图吞掉，否则菜单就没了。
- **连线固定暗灰**：所有父子连线一律 `0xff4a4a4a`，不随提交颜色变化——提交色是前景，线是背景，两者刻意区分。分支头后面的 `[分支名]` 装饰文字也降成灰色。
- **当前提交高亮**：影片文件此刻停留的那条提交（当前分支的 tip）多画一圈高亮描边，用的是 BBS 主题色 `BBSSettings.primaryColor()`，一眼能找到「我现在在哪」。用户点选的提交另用白色外框，两种标记不混。
- **没有全节点描边**：普通节点只填色、不包边，避免整张图被白框糊住。
- **不显示文件路径**：图的表头只留「影片名 · 分支」，不显示服务器上的文件位置（前一版做过、已按用户要求撤回）。

### 17.2 判定当前提交

`UICommitGraph.currentCommit(String filmId)`：取 `FilmCommitClient.graph(filmId)`，`graph.branches.get(graph.current)` 是当前分支的 tip 提交 id；取不到时退回 `graph.head`。只有 `node.tip` 的节点参与比对，所以不会误标父提交。

- 颜色只存客户端：`config/bbs_together_commit_colors.json`，键为 `影片id<TAB>提交id`，值为 ARGB。默认 `Colors.GRAY`。原来的 `bbs_together_branch_colors.json` 不再读写。
