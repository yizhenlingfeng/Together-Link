# Together Link

**简体中文** | [English](README_en.md)

Together Link（模组 ID：`bbs_together`）是 [BBS FS](https://modrinth.com/mod/bbs-mod) 的多人协作扩展。主发布支持 Minecraft 1.20.1–1.20.4 的 Fabric 环境，并提供 Minecraft 1.21.11 的实验性兼容构建。它在保留 BBS 原有编辑体验的前提下，提供多人实时协作、影片版本历史、服务端权限与资产锁、资产同步及服务器审计。

> 1.20.1–1.20.4 使用同一个通用构建；1.21.11 使用独立构建，两者不可混用。

## 版本与前置

| 构建 | Minecraft | Java | Fabric Loader | BBS FS | 状态 |
|---|---|---|---|---|---|
| 通用构建 | 1.20.1 – 1.20.4 | 17+ | >= 0.15.6 | >= 2.6（推荐 2.7） | 主发布 |
| 1.21.11 兼容构建 | 1.21.11 | 21+ | >= 0.19.3 | 2.7-1.21.11 | 实验性 |

当前版本：**2.1**。Fabric API 为必需前置；许可证为 MIT。

## 功能概览

### 实时协作

| 功能 | 说明 |
|---|---|
| 玩家颜色 | 每名玩家分配独立颜色，用于高亮其选中内容与光标 |
| 共享光标 | 其他玩家的光标位置实时显示 |
| 选中同步 | 表单、关键帧、回放片段的选中状态广播给在线玩家 |
| 表单锁定 | 同一回放表单被占用时显示锁定，避免并发修改 |
| 回放交换 | 支持交换玩家之间的回放顺序 |

### 合作录制

| 功能 | 说明 |
|---|---|
| 邀请与认领 | 右键「录制回放」按钮邀请玩家，对方同意后进入选回放房间，每人认领一条回放 |
| 房间列表 | 左列回放可滚动，每行显示模型预览（跟随 BBS 的「列表模型预览」设置）、时长与关键帧数；右列是参与者与进度 |
| 只读进度面板 | 开始录制后房间转为只读：显示已交卷人数、录制用时与仍在录制的成员，已交卷者可留在面板上等合并 |
| 隐藏重录演员 | 录制期间隐藏本次会话已认领回放的旧身体，避免上一场的演员与真人同时出现在片场 |
| 自动合并 | 全员交卷后服务端自动合并回放数据，并广播给所有参与者 |

### 影片、提交与分支

| 功能 | 说明 |
|---|---|
| 影片同步 | 影片选择、屏幕状态、关键帧/轨道修改实时推送 |
| 列表同步 | 新增、重命名、删除影片后所有客户端刷新 |
| 提交 | 每部影片保留提交图、快照和差异，默认最多 300 条 |
| 保存即提交 | 手动保存会把当前修改提交到玩家当前分支；周期保存只更新工作副本 |
| 分支隔离 | 每名玩家可在独立分支工作，互不覆盖 |
| 退回/压缩 | 支持保留或删除后续提交的退回，以及压缩连续提交 |
| 提交详情 | 显示提交信息、作者、时间、剪辑/关键帧统计和差异 |
| 提交图 | 按影片分列、按时间排列，可见区域外连线自动裁剪 |
| 提交颜色 | 服务端保存并广播，所有玩家看到一致颜色 |

### 权限与资产锁

| 功能 | 说明 |
|---|---|
| 三级权限 | 0 只读 / 1 编辑 / 2 管理，按功能域细分 |
| 功能域 | 伪装、影片、录制、模型方块、粒子、模型编辑器、纹理、音频、上传 |
| 资产锁 | 模型、影片、模型方块可限制为白名单/黑名单 |
| 锁显示 | 无权限者看到闭合锁；创建者/管理员看到管理标记 |
| 锁保护 | 服务端复核上传、保存、右键和破坏；锁定方块不可被无权限玩家破坏或打开 |
| 锁定入口 | 模型与影片的锁都是右键菜单顶部的图标，模型锁紧邻「添加类别」的加号；剪辑锁位于相机时间轴右键图标的 ≡（预设）之后 |
| 文件锁 | 影片保存、改名、删除、撤销和文件夹操作统一经过 `FilmWriteGuard` |
| 剪辑锁 | 相机时间轴可逐个锁定剪辑，限制为白名单或黑名单；锁写在剪辑自身的数据里，随影片保存 |
| 剪辑锁显示 | 锁定剪辑的条上带锁标记；无权限者的属性面板变灰，「编辑」按钮显示为锁按钮 |
| 剪辑锁保护 | 服务端复核整片快照与相机同步，越权改动还原为分支副本；增删锁仅限 2 级 |

### 资产同步

| 功能 | 说明 |
|---|---|
| 清单同步 | 服务器下发 assets 的 SHA-1、大小和 mtime |
| 自动下载/上传 | 客户端按清单差异自动同步缺失或变更文件 |
| 冲突仲裁 | 上传携带服务器 mtime 作为 CAS 令牌，避免覆盖他人修改 |
| 原子落盘 | 服务端本地校验 SHA-1，临时文件原子替换 |
| 分片隔离 | 多分片临时文件按玩家隔离，校验累计大小 |
| 大小上限 | 服务端和客户端共享 `asset_sync_max_mb` |
| CDN（可选） | 只读下载回退：优先 CDN，校验失败自动回退服务器 |
| 形态类别 | BBS 用户类别存到 `assets/form_categories/`，随资产同步在玩家间共享；旧的 `settings/forms` 首次启动自动迁入 |
| 防复活 | 模型删除 tombstone 持久化，离线客户端不能重新传回 |
| 恢复 | `/bbstogether restore <模型>` 清除 tombstone 后允许重新上传 |

### 服务器审计

| 功能 | 说明 |
|---|---|
| 行为面板 | 记录编辑、下载、上传、删除请求等行为 |
| 去重合并 | 连续重复操作合并，未实际变更不产生记录 |
| 来源标记 | 客户端自报记录显示“客户端上报（未由服务端核实）” |
| 权限保护 | 非 OP 玩家匿名显示；日志删除仅 OP 或 BBS 等级 2 |
| 持久化 | `<存档>/bbs/behaviors/`，UTF-8 + 原子写 |
| 限流 | 行为上报与 manifest 查询按玩家限流 |

## 权限等级

| 等级 | 名称 | 能力 |
|---|---|---|
| 0 | 只读 | 浏览、下载；不可编辑、上传或管理 |
| 1 | 编辑 | 默认可编辑全部域；管理员可逐域限制 |
| 2 | 管理 | 编辑全部内容，管理玩家等级、功能域和资产锁 |

- 单人/LAN 存档的集成服务器会自动给开服者 2 级。
- 专用服不再自动把第一个进服玩家设为管理员；首次开服请由控制台执行 `/bbsop <玩家> 2`。
- 只有 BBS 等级 2 能始终绕过资产锁；锁创建者被降级后同样受锁限制。

## 服务器命令

| 命令 | 说明 | 权限 |
|---|---|---|
| `/bbstogether record <玩家>` | 切换目标玩家录制状态 | OP |
| `/bbstogether restore <模型>` | 清除模型删除 tombstone，允许重新上传 | OP 或 BBS 2 |
| `/bbstogether diag` | 输出资产同步/队列诊断 | OP |
| `/bbsop <玩家> [0-2]` | 查询或设置 BBS 权限等级 | OP/控制台/BBS 2 |
| `/bbsop <玩家> grant <域> <allow\|deny>` | 允许/禁止等级 1 的某个域 | OP/控制台/BBS 2 |
| `/bbsop <玩家> grant reset` | 恢复等级 1 为不受限 | OP/控制台/BBS 2 |

功能域：`morph`、`film`、`record`、`model_blocks`、`particles`、`model_editor`、`textures`、`audio`、`upload`。

## 安装与部署

| 步骤 | 操作 |
|---|---|
| 1 | 安装 Minecraft 1.20.1 或 1.20.4、Fabric Loader、Fabric API、对应版本的 BBS FS |
| 2 | 将 `together-link-2.1-1.20.1-1.20.4.jar` 放入客户端和服务端的 `mods/` |
| 3 | 启动服务器，使用控制台或 OP 执行 `/bbsop <玩家> 2` 初始化管理员 |
| 4 | 所有客户端连接同一服务器；服务端与客户端必须使用同一版本 |
| 5 | 进入 BBS 仪表盘即可开始协作 |

> 仅更新客户端不会生效：资产路径、权限、CAS、tombstone、合作录制锁等服务端校验都在服务端执行。
>
> 1.21.11 兼容构建的安装方式相同，但需使用 `together-link-2.1-1.21.11.jar` 和 BBS `2.7-1.21.11`。1.20.x 与 1.21.11 属于不同构建，不能混用。

## 配置

配置文件：`config/bbs/settings/bbs_together.json`。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `cdn.url` / `cdn.token` | 空 | 可选只读 CDN 下载源；失败自动回退服务器 |
| `cdn.download` | 开 | 自动下载缺失资产 |
| `cdn.upload` | 开 | 自动上传本地变更 |
| `cdn.receive` | 开 | 接收服务器资产推送 |
| `cdn.progress_bar` | 开 | 显示左下角同步状态组件 |
| `cdn.progress_bar_always` | 关 | 空闲时显示小状态点 |
| `server.auto_sync` | 关 | 自动监听资产变更 |
| `server.asset_sync_max_mb` | 256 | 单文件大小上限，0 = 不限制 |
| `server.asset_upload_kbps` | 0 | 客户端上传限速，0 = 不限速 |
| `server.asset_egress_kbps` | 0 | 服务端总出口限速，0 = 不限速 |
| `server.asset_ingress_kbps` | 0 | 服务端总入口限速，0 = 不限速 |
| `behaviors.behavior_log_limit` | 1000 | 行为日志条数上限 |
| `coop.coop_invite_seconds` | 60 | 合作录制邀请有效期（秒） |

## 兼容性

| 场景 | 行为 |
|---|---|
| BBS-only/原版服务器 | 不启用 Together 权限与同步，BBS 编辑保持可用 |
| 旧版 Together 服务器 | 通过首个权限同步包识别，保持兼容 |
| BBS-Cubed | 右键菜单在分类构建阶段过滤，保留 addon 追加项 |
| 影片分支 | 非默认分支保存写入分支存储，不覆盖主影片 |
| CDN | 只读下载回退；不支持 CDN 上传或 CDN manifest |
| 冲突令牌 | 基于服务器 mtime 的 CAS，不是严格单调 revision |
| 行为日志 | 有来源标记、类型/长度校验和限流；无服务端签名/审计链 |

## 构建

| 命令 | 说明 |
|---|---|
| `.\gradlew.bat build` | 构建通用产物（1.20.1 / 1.20.4） |
| `build/libs/together-link-2.1-1.20.1-1.20.4.jar` | 主发布产物 |
| `.\gradlew.bat build "-Pmcver=1.20.4"` | 仅编译/运行验证 1.20.4，产物带 `-verify`，不发布 |
| `.\gradlew.bat build12111` | 构建 1.21.11 兼容产物（实验性，单独发布） |
| `.\gradlew.bat runClient12111` | 启动 1.21.11 开发客户端（`run-1.21.11-client/`） |
| `.\gradlew.bat runClient12111B` | 启动第二个 1.21.11 开发客户端（`run-1.21.11-client-b/`） |
| `.\gradlew.bat runServer12111` | 启动 1.21.11 开发服务器（`run-1.21.11-server/`） |
| `dist/` | 发布副本 |

构建工具 Loom 固定为 `1.15.5`，避免快照版本导致构建差异。

`runClient12111` 和 `runClient12111B` 支持用 `-PjoinServer=127.0.0.1:25565` 在启动后直接加入服务器：

```powershell
.\gradlew.bat runServer12111 --console=plain
.\gradlew.bat runClient12111  '-PjoinServer=127.0.0.1:25565'
.\gradlew.bat runClient12111B '-PjoinServer=127.0.0.1:25565'
```

> **1.21.11 兼容构建（实验性）：** 这是独立于 1.20.x 主发布的兼容产物。它复用 1.20 的公共源码，并通过 `src/main/java-1.21.11`、`src/client/java-1.21.11` 薄覆盖层适配 1.21.11 的网络、渲染与 Mixin API。已完成编译、专用服务器加入、双客户端加入、9 MB 大资产传输与出入口限速验证；尚未完成 30 分钟长连接、持续同步和锁竞争压测，也不承诺与 1.20.x 世界存档互通。构建前需先将 BBS `2.7-1.21.11` 从 `lib/bbs-fs-1.21.11` 发布到 mavenLocal。测试记录见 [1.21.11 测试记录](docs/12111-p5-checkpoint.md)。

## 更新日志

### v2.1

#### 新增

- 合作录制房间重新设计：面板跟随 BBS 界面缩放（右下角可拖动调整尺寸，调整后的尺寸会被记住），顶部显示影片、分支与录制阶段，左侧是可滚动的回放列表，右侧是参与者名单，底部是状态提示与操作按钮。回放数量超过面板高度时可用鼠标滚轮或滚动条浏览。
- 每条回放新增模型预览，取该回放绑定表单的模型，跟随 BBS 设置中的「列表模型预览」开关；同时显示时长与关键帧数，并标出第一人称、演员与未启用状态。已认领的回放显示认领者的头像与名字，自己的回放高亮。预览只读取本地影片副本，不会把收到的影片写入磁盘，因此打开房间不会覆盖玩家尚未保存的编辑。
- 录制阶段房间转为只读进度面板：显示已交卷人数与进度条、录制用时，以及仍在录制的成员名单。已交卷的玩家交卷后自动回到该面板查看进度，不必留在片场等待。
- 保存或提交的影片回放数量为 0 时输出诊断日志，便于判断空数据来自客户端还是服务端工作副本。
- 模型锁定入口改为右键菜单顶部的图标，与「添加类别」的加号并排，不再占用菜单列表中的一行；点击后仍是原来的锁定子菜单。
- 形态类别（形态面板里的「类别」文件夹）纳入服务器资产同步。类别文件原本只存在本地 `config/bbs/settings/forms`，清单、下发和上传都不覆盖它，因此玩家整理的类别从来不会同步给其他人。现在改为存放在服务器资产目录下的 `form_categories/`，直接复用现有的 SHA-1 比对、mtime 仲裁、分片传输与上传权限；收到服务器下发的类别文件后自动重读类别列表，首次启动会把旧文件复制到新目录（旧目录保留）。
- 相机时间轴新增逐个剪辑的锁定：右键剪辑后，图标栏在 ≡（预设）之后多出一个锁图标，可把该剪辑限制为禁止所有人编辑、允许白名单或黑名单玩家编辑，或解除锁定。锁记录在剪辑自身的数据里（键 `bbs_together:clip_lock`），因此随影片一起保存，复制、粘贴与撤销都带着它走；服务端按锁内自带的随机 ID 匹配剪辑，不依赖会随排序变化的下标。
- 锁定效果直接画在时间轴上：锁定剪辑的条上带锁标记；没有编辑权限的玩家选中它时，右侧属性面板整体变灰，「关键帧 → 编辑」按钮由 BBS 自带的锁定遮罩显示为锁按钮且无法点击，拖拽、剪切、移除、对齐光标与双击打开也都不再生效。
- 锁在改动当下就广播给同分支的其他编辑者，并写入服务端的分支副本，因此重进或重启后仍然保留。此前相机剪辑不参与整片保存，锁只存在于加锁者的客户端，旁观者照常可以修改。
- 服务端复核两类写入：整片快照里被锁剪辑的越权改动会还原为分支副本中的那一份，玩家的其他合法改动照常保存；时间轴同步里命中被锁剪辑的写入直接丢弃并给出提示。新建、修改与解除锁只有 2 级权限可以执行。
- 新增影片提交图页签（`影片节点`）：把每个影片的分支与提交画成一张可上下滚动的节点图，主分支居中、其他分支左右分开，点击节点可查看详情、重命名、回退、压缩与切换分支；新提交到达时自动刷新并跟随到底部。
- 剪辑右键菜单新增剪贴板校验：打开菜单时先检查系统剪贴板是否为可解析的 BBS 数据，不是时按「不可粘贴」处理、粘贴按钮置灰。此前剪贴板里是任意文本（例如一段日志或崩溃报告）时会抛出解析异常并把客户端带崩。

#### 修复

- 修复重新发起合作录制时，上一场录制的回放演员仍留在片场、与真人形成两批演员的问题。录制期间隐藏本次会话已认领回放的旧身体（含已交卷但尚未合并的成员）；未被任何人认领的回放保留身体，继续作为站位参考。
- 修复修改影片回放数量后提交，其他玩家不同步、提交的回放被清空的问题。结构同步在重建回放列表后调用了 `ValueStableList.sync()`，而该方法在 BBS 中恒定抛出 `UnsupportedOperationException`；异常又发生在服务端 `execute` 调度内被静默丢弃，于是保存和转发都被跳过，新增回放也没有填入数据。现在改为按载荷中的 id 先构建回放、再替换列表，并移除该调用。
- 结构同步增加载荷校验：只有载荷是列表、且条数与元数据一致时才应用。此前收到不匹配的载荷会先清空整张回放表，是影片变成 0 条回放的入口；应用失败时记录日志，不再静默中断。
- 修复合作录制结束通知显示为原始键名（如 `bbs_together.coop.notify.merged`）的问题：这些键此前只写进原版语言表，实际却由 BBS 的语言表解析。
