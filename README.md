# Together Link

**简体中文** | [English](README_en.md)

Together Link（模组 ID：`bbs_together`）是 [BBS FS](https://modrinth.com/mod/bbs-mod) 的多人协作扩展。主发布支持 Minecraft 1.20.1–1.20.4 的 Fabric 环境，并提供 Minecraft 1.21.11 的实验性兼容构建。它在保留 BBS 原有编辑体验的前提下，提供多人实时协作、影片版本历史、服务端权限与资产锁、资产同步及服务器审计。

> 1.20.1–1.20.4 使用同一个通用构建；1.21.11 使用独立构建，两者不可混用。

## 版本与前置

| 构建 | Minecraft | Java | Fabric Loader | BBS FS | 状态 |
|---|---|---|---|---|---|
| 通用构建 | 1.20.1 – 1.20.4 | 17+ | >= 0.15.6 | >= 2.6（推荐 2.7） | 主发布 |
| 1.21.11 兼容构建 | 1.21.11 | 21+ | >= 0.19.3 | 2.7-1.21.11 | 实验性 |

当前版本：**2.1**。Fabric API 为必需前置；许可证为 MIT。

## 功能概览

### 实时协作

| 功能 | 说明 |
|---|---|
| 玩家颜色 | 每名玩家分配独立颜色，用于高亮其选中内容与光标 |
| 共享光标 | 其他玩家的光标位置实时显示 |
| 选中同步 | 表单、关键帧、回放片段的选中状态广播给在线玩家 |
| 表单锁定 | 同一回放表单被占用时显示锁定，避免并发修改 |
| 回放交换 | 支持交换玩家之间的回放顺序 |

### 合作录制

| 功能 | 说明 |
|---|---|
| 邀请与认领 | 右键「录制回放」按钮邀请玩家，对方同意后进入选回放房间，每人认领一条回放 |
| 房间列表 | 左列回放可滚动，每行显示模型预览（跟随 BBS 的「列表模型预览」设置）、时长与关键帧数；右列是参与者与进度 |
| 只读进度面板 | 开始录制后房间转为只读：显示已交卷人数、录制用时与仍在录制的成员，已交卷者可留在面板上等合并 |
| 隐藏重录演员 | 录制期间隐藏本次会话已认领回放的旧身体，避免上一场的演员与真人同时出现在片场 |
| 自动合并 | 全员交卷后服务端自动合并回放数据，并广播给所有参与者 |

### 影片、提交与分支

| 功能 | 说明 |
|---|---|
| 影片同步 | 影片选择、屏幕状态、关键帧/轨道修改实时推送 |
| 列表同步 | 新增、重命名、删除影片后所有客户端刷新 |
| 影片列表 | 左栏显示每部影片的提交数、当前分支和最近提交时间，支持搜索、全部/已显示/当前筛选与按名称、最近提交、提交数排序 |
| 提交 | 每部影片保留提交图、快照和差异，默认最多 300 条 |
| 保存即提交 | 手动保存会把当前修改提交到玩家当前分支；周期保存只更新工作副本 |
| 分支隔离 | 每名玩家可在独立分支工作，互不覆盖 |
| 退回/压缩 | 支持保留或删除后续提交的退回，以及压缩连续提交 |
| 提交详情 | 底部详情栏显示完整提交信息、作者、时间、剪辑/关键帧统计和改动摘要，可拖动调整高度 |
| 提交图 | 按影片分列、按时间排列；列头显示提交、信息、改动、作者与时间，按日期分组，窄栏自动收起次要列 |
| 节点操作 | 右键可复制短/完整哈希、复制提交信息、重命名、回退、压缩、切分支、定位 HEAD、隐藏影片或设置提交颜色；支持 ↑/↓、Enter 与 Ctrl+C |
| 提交颜色 | 服务端保存并广播，所有玩家看到一致颜色 |

### 权限与资产锁

| 功能 | 说明 |
|---|---|
| 三级权限 | 0 只读 / 1 编辑 / 2 管理，按功能域细分 |
| 功能域 | 伪装、影片、录制、模型方块、粒子、模型编辑器、纹理、音频、上传 |
| 资产锁 | 模型、影片、模型方块可限制为白名单/黑名单 |
| 锁显示 | 无权限者看到闭合锁；创建者/管理员看到管理标记 |
| 锁保护 | 服务端复核上传、保存、右键和破坏；锁定方块不可被无权限玩家破坏或打开 |
| 锁定入口 | 模型与影片的锁都是右键菜单顶部的图标，模型锁紧邻「添加类别」的加号；剪辑锁位于相机时间轴右键图标的 ≡（预设）之后 |
| 文件锁 | 影片保存、改名、删除、撤销和文件夹操作统一经过 `FilmWriteGuard` |
| 剪辑锁 | 相机时间轴可逐个锁定剪辑，限制为白名单或黑名单；锁写在剪辑自身的数据里，随影片保存 |
| 剪辑锁显示 | 锁定剪辑的条上带锁标记；锁对当前玩家生效时菜单图标为闭合的锁，白名单内可编辑的玩家看到打开的锁；无权限者的属性面板变灰，「编辑」按钮显示为锁按钮 |
| 剪辑锁保护 | 服务端复核整片快照与相机同步，越权改动还原为分支副本；增删锁需 BBS 等级 1 以上，等级 2 可绕过锁继续编辑 |
| 编辑锁定关键帧 | 项目设置的关键帧栏开关（默认关）。开启后，打开某个剪辑的关键帧编辑区即自动锁定该剪辑；关闭该区即自动解除，且只解除本次自动锁，管理员手动锁保留。锁定期间仅自己与同一时间在编辑该剪辑的玩家可继续修改，包括他们后进入的伙伴；其他人既不能打开关键帧编辑区，也不能在时间轴上改动它 |
| 关键帧锁 | 关键帧编辑器右键菜单的锁图标，可把选中的关键帧区间整体锁定；支持跨轨道多选，回放轨道与相机剪辑的关键帧编辑器均可用。图标对所有人可见：2 级玩家按鼠标下有无锁显示开锁/关锁，其余玩家在锁生效时显示关锁且按钮不可点击 |
| 关键帧锁范围 | 选区必须包含首尾之间的全部关键帧；区间内若含循环关键帧，则整个循环块一并锁定，无法选中、拖动、缩放或删除 |
| 关键帧锁显示 | 锁定区间在时间轴上并成一块带虚线边框和锁标记的遮罩，仅在共用外沿描边；锁定关键帧不会进入选区，也不能拖动或删除。等级 1 以上的玩家看到用于增删锁的打开标记，其余玩家看到闭合锁且不可点击 |
| 关键帧锁同步 | 锁写在所属回放或相机剪辑的命名空间键里，增删锁即时广播并写入服务端副本；服务端按区间合并接收，较旧的快照不会抹掉他人刚加的锁 |
| 关键帧锁保护 | 锁内数据对所有玩家只读，等级 1 以上只能增删锁，解锁后才能编辑；服务端复核增量同步、整片保存和撤销，Ctrl+Z 触及锁定内容时直接拒绝 |

### 资产同步

| 功能 | 说明 |
|---|---|
| 清单同步 | 服务器下发 assets 的 SHA-1、大小和 mtime |
| 自动下载/上传 | 客户端按清单差异自动同步缺失或变更文件 |
| 冲突仲裁 | 上传携带服务器 mtime 作为 CAS 令牌，避免覆盖他人修改 |
| 原子落盘 | 服务端本地校验 SHA-1，临时文件原子替换 |
| 分片隔离 | 多分片临时文件按玩家隔离，校验累计大小 |
| 上传回执 | 服务端校验并落盘后才回执「成功」；拒绝时回具体原因码，客户端按瞬时/永久错误分别重试或放弃 |
| 清单回执 | 资产报表与影片清单带编号，服务端应用后回执；客户端收到回执才推进本地快照，避免丢包导致漏报 |
| 发送拒绝回执 | 服务器发送队列满或分片未发完时回执原因，客户端有界重试，不再把未送达当成已完成 |
| 大小上限 | 服务端和客户端共享 `asset_sync_max_mb` |
| CDN（可选） | 只读下载回退：优先 CDN，校验失败自动回退服务器 |
| 形态类别 | BBS 用户类别存到 `assets/form_categories/`，随资产同步在玩家间共享；旧的 `settings/forms` 首次启动自动迁入 |
| 防复活 | 模型删除 tombstone 持久化，离线客户端不能重新传回 |
| 恢复 | `/bbstogether restore <模型>` 清除 tombstone 后允许重新上传 |

### 服务器审计

| 功能 | 说明 |
|---|---|
| 行为面板 | 记录编辑、下载、上传、删除请求等行为 |
| 去重合并 | 连续重复操作合并，未实际变更不产生记录 |
| 来源标记 | 客户端自报记录显示“客户端上报（未由服务端核实）” |
| 权限保护 | 非 OP 玩家匿名显示；日志删除仅 OP 或 BBS 等级 2 |
| 持久化 | `<存档>/bbs/behaviors/`，UTF-8 + 原子写 |
| 限流 | 行为上报与 manifest 查询按玩家限流 |

## 权限等级

| 等级 | 名称 | 能力 |
|---|---|---|
| 0 | 只读 | 浏览、下载；不可编辑、上传或管理 |
| 1 | 编辑 | 默认可编辑全部域；管理员可逐域限制 |
| 2 | 管理 | 编辑全部内容，管理玩家等级、功能域和资产锁 |

- 单人/LAN 存档的集成服务器会自动给开服者 2 级。
- 专用服不再自动把第一个进服玩家设为管理员；首次开服请由控制台执行 `/bbsop <玩家> 2`。
- 等级 1 以上可以创建、修改和解除资产锁、剪辑锁与关键帧锁；只有等级 2 能始终绕过锁继续编辑。锁创建者被降级后同样受锁限制。

## 服务器命令

| 命令 | 说明 | 权限 |
|---|---|---|
| `/bbstogether record <玩家>` | 切换目标玩家录制状态 | OP |
| `/bbstogether restore <模型>` | 清除模型删除 tombstone，允许重新上传 | OP 或 BBS 2 |
| `/bbstogether diag` | 输出资产同步/队列诊断 | OP |
| `/bbsop <玩家> [0-2]` | 查询或设置 BBS 权限等级 | OP/控制台/BBS 2 |
| `/bbsop <玩家> grant <域> <allow\|deny>` | 允许/禁止等级 1 的某个域 | OP/控制台/BBS 2 |
| `/bbsop <玩家> grant reset` | 恢复等级 1 为不受限 | OP/控制台/BBS 2 |

功能域：`morph`、`film`、`record`、`model_blocks`、`particles`、`model_editor`、`textures`、`audio`、`upload`。

## 安装与部署

| 步骤 | 操作 |
|---|---|
| 1 | 安装 Minecraft 1.20.1 或 1.20.4、Fabric Loader、Fabric API、对应版本的 BBS FS |
| 2 | 将 `together-link-2.1-1.20.1-1.20.4.jar` 放入客户端和服务端的 `mods/` |
| 3 | 启动服务器，使用控制台或 OP 执行 `/bbsop <玩家> 2` 初始化管理员 |
| 4 | 所有客户端连接同一服务器；服务端与客户端必须使用同一版本 |
| 5 | 进入 BBS 仪表盘即可开始协作 |

> 仅更新客户端不会生效：资产路径、权限、CAS、tombstone、合作录制锁等服务端校验都在服务端执行。
>
> 1.21.11 兼容构建的安装方式相同，但需使用 `together-link-2.1-1.21.11.jar` 和 BBS `2.7-1.21.11`。1.20.x 与 1.21.11 属于不同构建，不能混用。

## 配置

配置文件：`config/bbs/settings/bbs_together.json`。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `cdn.url` / `cdn.token` | 空 | 可选只读 CDN 下载源；失败自动回退服务器 |
| `cdn.download` | 开 | 自动下载缺失资产 |
| `cdn.upload` | 开 | 自动上传本地变更 |
| `cdn.receive` | 开 | 接收服务器资产推送 |
| `cdn.progress_bar` | 开 | 显示左下角同步状态组件 |
| `cdn.progress_bar_always` | 关 | 空闲时显示小状态点 |
| `server.auto_sync` | 关 | 自动监听资产变更 |
| `server.asset_sync_max_mb` | 256 | 单文件大小上限，0 = 不限制 |
| `server.asset_upload_kbps` | 0 | 客户端上传限速，0 = 不限速 |
| `server.asset_egress_kbps` | 0 | 服务端总出口限速，0 = 不限速 |
| `server.asset_ingress_kbps` | 0 | 服务端总入口限速，0 = 不限速 |
| `behaviors.behavior_log_limit` | 1000 | 行为日志条数上限 |
| `coop.coop_invite_seconds` | 60 | 合作录制邀请有效期（秒） |
| `edit_lock_clips`（关键帧栏） | 关 | 打开剪辑的关键帧编辑区时自动锁定该剪辑，关闭编辑区即解除。仅自己与同一时间在编辑该剪辑的玩家可继续修改；只解除自动锁，手动锁保留 |

## 兼容性

| 场景 | 行为 |
|---|---|
| BBS-only/原版服务器 | 不启用 Together 权限与同步，BBS 编辑保持可用 |
| 旧版 Together 服务器 | 通过首个权限同步包识别，保持兼容 |
| BBS-Cubed | 右键菜单在分类构建阶段过滤，保留 addon 追加项 |
| 影片分支 | 非默认分支保存写入分支存储，不覆盖主影片 |
| CDN | 只读下载回退；不支持 CDN 上传或 CDN manifest |
| 冲突令牌 | 基于服务器 mtime 的 CAS，不是严格单调 revision |
| 行为日志 | 有来源标记、类型/长度校验和限流；无服务端签名/审计链 |

## 构建

| 命令 | 说明 |
|---|---|
| `.\gradlew.bat build` | 构建通用产物（1.20.1 / 1.20.4） |
| `build/libs/together-link-2.1-1.20.1-1.20.4.jar` | 主发布产物 |
| `.\gradlew.bat build "-Pmcver=1.20.4"` | 仅编译/运行验证 1.20.4，产物带 `-verify`，不发布 |
| `.\gradlew.bat build12111` | 构建 1.21.11 兼容产物（实验性，单独发布） |
| `.\gradlew.bat runClient12111` | 启动 1.21.11 开发客户端（`run-1.21.11-client/`） |
| `.\gradlew.bat runClient12111B` | 启动第二个 1.21.11 开发客户端（`run-1.21.11-client-b/`） |
| `.\gradlew.bat runServer12111` | 启动 1.21.11 开发服务器（`run-1.21.11-server/`） |
| `dist/` | 发布副本 |

构建工具 Loom 固定为 `1.15.5`，避免快照版本导致构建差异。

`runClient12111` 和 `runClient12111B` 支持用 `-PjoinServer=127.0.0.1:25565` 在启动后直接加入服务器：

```powershell
.\gradlew.bat runServer12111 --console=plain
.\gradlew.bat runClient12111  '-PjoinServer=127.0.0.1:25565'
.\gradlew.bat runClient12111B '-PjoinServer=127.0.0.1:25565'
```

> **1.21.11 兼容构建（实验性）：** 这是独立于 1.20.x 主发布的兼容产物。它复用 1.20 的公共源码，并通过 `src/main/java-1.21.11`、`src/client/java-1.21.11` 薄覆盖层适配 1.21.11 的网络、渲染与 Mixin API。已完成编译、专用服务器加入、双客户端加入、9 MB 大资产传输与出入口限速验证；尚未完成 30 分钟长连接、持续同步和锁竞争压测，也不承诺与 1.20.x 世界存档互通。构建前需先将 BBS `2.7-1.21.11` 从 `lib/bbs-fs-1.21.11` 发布到 mavenLocal。测试记录见 [1.21.11 测试记录](docs/12111-p5-checkpoint.md)。

## 更新日志

### v2.1

#### 新增

- 合作录制房间重设计：可缩放面板，显示影片、分支、录制阶段、回放列表（含模型预览、时长、关键帧数与认领者）和参与者名单；录制阶段转为只读进度面板。
- 模型锁入口改为右键菜单顶部图标，与「添加类别」的加号并排。
- 形态类别文件夹纳入服务器资产同步（存于 `form_categories/`，复用现有分片与权限）。
- 相机时间轴可逐个锁定剪辑：右键菜单 ≡ 之后新增锁图标，可设为禁止所有人、白名单、黑名单或解除。锁写在剪辑数据里（`bbs_together:clip_lock`），随影片保存，复制、粘贴、撤销一并带走；服务端按锁内随机 ID 匹配。
- 锁定效果画在时间轴上：条上带锁标记；无权限者选中后面板变灰，「关键帧 → 编辑」显示为锁按钮且无法点击，拖拽、剪切、移除、对齐光标、双击打开均失效。锁图标跟随当前玩家：锁对其生效时显示闭合的锁，白名单内允许编辑的玩家显示打开的锁。锁即时广播给同分支玩家并写入服务端副本，服务端复核整片快照与相机同步，越权改动被还原；增删锁需 BBS 等级 1 以上。
- 关键帧可锁定区间：关键帧编辑器右键菜单在预设按钮右侧新增锁图标，可把多选的关键帧整体锁定。选区必须包含首尾之间的全部关键帧，区间内若有循环关键帧则连带整个循环块一起锁定，因此锁定的循环无法选中、拖动、缩放或删除；回放轨道与相机剪辑的关键帧编辑器都适用。
- 关键帧锁的显示与保护：锁定区间在时间轴上合并为带虚线外框和锁标记的遮罩。锁内数据对所有玩家只读，等级 1 以上的玩家只能增删锁，解锁后才能编辑；锁区外撤销不受影响，触及锁区的修改与撤销会被拒绝并恢复。锁图标对所有人可见，菜单首行显示当前选区能否锁定，解除锁定时整条锁定记录一并解除。
- 重构「影片节点」页签的布局与配色：顶栏、影片索引、提交图与详情栏分层显示；左栏增宽并支持搜索、按全部/已显示/当前筛选，以及按名称、最近提交、提交数排序，每部影片显示提交数、当前分支与最近提交时间。
- 提交图增加固定列头与按日期分隔：提交、信息、改动、作者、时间五列对齐显示，窄栏按时间、作者、改动的顺序自动收起；提交哈希与正文提高对比度，当前分支/HEAD 可一键定位，长历史支持 ↑/↓ 选择、Enter 查看与 Ctrl+C 复制短哈希（Shift 复制完整哈希）。
- 底部详情栏改为可拖动的双栏：左侧显示完整提交信息、作者与时间、剪辑/关键帧统计及改动分节，右侧汇总改动数量；右键节点可复制短/完整哈希或提交信息、重命名、回退、压缩、切分支、隐藏影片及设置提交颜色。
- 剪辑右键菜单先校验剪贴板：非 BBS 数据按「不可粘贴」处理、粘贴按钮置灰（此前任意文本会解析异常带崩客户端）。
- 资产同步改为「服务端确认后才算完成」：上传落盘、资产报表、影片清单、服务器发送四条链路都会回执，客户端据此推进本地状态，不再出现「显示已完成但服务器没有」。
- 新增「编辑锁定关键帧」开关（项目设置的关键帧栏，默认关闭）：开启后，打开某个剪辑的关键帧编辑区即自动把该剪辑锁给自己，关闭编辑区即自动解除。锁定期间同一时间正在编辑该剪辑的玩家可以继续一起编辑，后来者既进不了关键帧编辑区，也不能在时间轴上改动它；解除时只移除本次自动锁，管理员手动设置的锁保留。开关由各自的客户端决定，只在网络协议 6 及以上的服务器生效。

#### 修复

- 重新发起合作录制时，隐藏上一场已认领回放的旧身体，避免与真人形成两批演员。
- 修改回放数量后提交不同步、回放被清空：移除会抛异常的 `ValueStableList.sync()`，改为按载荷 id 重建再替换列表；并增加载荷校验，条数不一致时不应用。
- 合作录制结束通知显示为原始键名（改为由 BBS 语言表解析）。
- 录制中关闭聊天栏或物品栏后，房间面板不再重新盖到世界画面上。
- 「影片节点」每次启动后首次打开节点挤顶且不能滚动，现在量出尺寸即重排、每帧补布局，首次打开即正确。
- 撤销（Ctrl+Z）可以改写已锁定的关键帧：回滚记录的是锁定之前的数值，此前只在服务端复核增量同步时才会发现，客户端仍会把回滚写回画面。现在客户端在撤销、重做前先比对锁定区间，触及锁定内容时直接拒绝并提示「撤销会修改已锁定的关键帧」；服务端对撤销改用更严格的判定，锁定记录、关键帧或循环块任一被回滚都会被拒绝并回推镜像值。
- 资产与影片同步整体失效：包大小保护把「整包长度」当作判断依据，而实际的网络包在发送前会被切成 30,000 字节一片，因此所有超过 32,767 字节的内容（整部影片、资产清单、提交图、行为列表）在分片前就被整包丢弃，表现为同步「无声失败」。现在只对切片后的单个包做检查，任意大小都能正确发出。
- 空载荷通道被误拦：撤销同步、拒绝合作邀请、非当前影片的提交创建都会发送空数据，此前的检查把 0 字节判为非法而丢弃。现在 0 字节按原协议的哨兵字节正常传输。
- 撤销同步在较大增量下丢包：撤销数据原先写在分片的尾部附加字段里，而附加字段只会追加到最后一片，片大时会把最后一片撑过上限并整包丢弃。现在撤销数据进入被分片的正文字段，可以任意大。
- 提交信息过长导致的末片溢出：提交说明原先无长度限制地写在尾部，与接近满片的正文叠加时同样会超出单片上限。现在按服务端的实际读取长度截断。
- 影片保存卡服与「保存了但别人看不到」：解析、合并、序列化与写盘全部移到独立线程，主线程只做引用替换与广播；同时改为「先落盘再广播」，查看端不会收到服务器尚未保存的状态。
- 大文件传输期间服务器丢 tick：资产下发的读盘操作移到发送线程，实时编辑与影片保存的载荷解析移出网络线程，避免单个大包占住事件循环导致他人延迟或 30 秒读超时。
- 进服时按影片数量线性卡顿：影片清单原先对每部影片各提交一次主线程任务，服务器影片多时进服会连续卡顿；现在在后台一次性收集后统一广播。
- 长跑内存持续上涨：服务端影片快照缓存、资产哈希缓存与客户端的服务器清单快照都改为有上限的 LRU，打开再多影片或反复进服也不会线性增长。
- 关键帧锁调整为全玩家只读：锁内关键帧与循环块对所有人不可修改；等级 1 以上负责创建和解除锁，解锁后恢复编辑。
- 补齐锁区编辑拦截：属性面板、缓动中点、循环菜单、Ctrl+左键、粘贴与堆叠、录制与飞行剪辑、回放位移和旋转 Gizmo 均不能写入锁区；直接通道替换也会恢复锁定内容，未闭合的通道事务不会形成后续编辑豁免。
- 完善锁区撤销与同步：锁区外撤销正常执行，触及锁区时拒绝；服务端校验所有者快照、目标 tick 和索引，拒绝修改后回发所属通道，避免本地与服务端不一致。
- 剪辑中右键锁定关键帧的菜单里出现一个白色方块：说明行误用了带颜色的菜单项重载，该重载会在图标列刷一块 22 像素的色块。现在改用普通菜单项，只显示文字。
- 1.21.11 客户端进服后断线（`readerIndex + length exceeds writerIndex`）：进度、颜色、选中、提交位置等状态通道在服务端改为分片发送后，客户端仍按未分片的数据读取，把分片头当成了字段。现在这些通道在客户端统一经分片器重组后再解析，发送端与接收端的格式保持一致。
- 无权限玩家无法加锁，必须再锁一次才生效：服务端原先只在「所有者没有锁、且载荷也没有锁」时放行，其余一律拒绝。客户端本地已写入锁，服务端那份却仍未写入，于是要再点一次才对齐。现在按锁范围判定：载荷仍覆盖所有者当前持有的每一条锁即放行，只有会删除或收窄既有锁的请求才被拒绝。
- 加锁后回退到上一次修改：BBS 读取所有者数据时会先清空命名空间键再按载荷重建，而锁记录就存在其中，一个稍旧的快照会把他人刚加的锁一并抹掉并写入磁盘。现在子值照常更新，命名空间键改为逐键合并，不再整体替换。
- 两名玩家看到的锁定框不在同一行：单通道曲线图模式下所有轨道都取同一个固定行高，而该模式只有一条通道、泳道实为整个绘图区。现在按绘图区高度绘制，与时间轴模式使用同一套行坐标。
- 锁定框边缘闪烁、错位，以及出现在未锁定轨道或折叠区域：虚线边框改为固定整数像素绘制，避免半像素抖动；只按真实通道 id 精确匹配，跳过折叠或筛选后不可见的轨道，避免前后缀误匹配和隐藏行被画到列表顶部。
- 关键帧锁的本地拦截一启动就崩溃（`InvalidInjectionException`）：新增的关键帧插入拦截挂在了 `UIKeyframes` 上，而该方法实际属于 `IUIKeyframeGraph` 接口。现在按完整签名注入正确目标，时间轴与曲线图两种实现同时生效。
- 资产锁与剪辑锁的白名单/黑名单菜单文案改为「白名单玩家」「黑名单玩家」，与列表内容一致。
- 锁定或解除锁定一个相机剪辑会多出一个提交节点：加锁后原会立即整片保存，服务端据此记录一次提交，即使影片内容并未改变。现在锁只经独立的数据同步通道广播给同分支玩家并写入服务端副本，不再触发整片保存，锁定剪辑不再产生提交。
- 等级 1 无法加锁：剪辑锁、关键帧锁与资产锁的锁菜单原先都只对等级 2 开放，现已改为等级 1 以上即可创建、修改和解除，等级 2 保留「无视锁继续编辑」的特权。
- 等级 2 正在编辑的剪辑，等级 1 仍能进去改：自动锁与手动锁原先各用一套放行规则，服务端复核整片快照时按锁 ID 匹配剪辑，剪辑被重排后匹配不上。现在两种锁统一按白名单放行，按锁 ID 找不到时回退到剪辑下标，共同编辑者的白名单会随锁更新合并，不再被服务端的旧副本覆盖。
- 编辑锁定关键帧在等级 1 玩家身上不生效：客户端要等服务器下发握手包才记下协议版本，而权限、锁等包先于握手到达，握手包被「已识别服务器」的判断提前丢弃，协议版本因此一直是 0，开关始终判定为不可用。现在无论两者先后到达都会记录协议版本。
- 已锁定剪辑仍可从时间轴双击进入关键帧编辑区：此前的拦截只覆盖时间轴上的选中与拖拽，打开剪辑走的是另一条入口。现在这条入口同样被拦截。
- 服务端提示显示为原始键名（如 `bbs_together.clip_lock.notify.locked`）：BBS 的语言表读 `assets/bbs_together/strings`，而原版客户端读 `assets/bbs_together/lang`，服务端发出的可翻译消息只查后者。现在两份语言表同时提供并由构建校验同步。
