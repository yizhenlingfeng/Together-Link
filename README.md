# Together Link

Together Link（原名 BBS Together）是 [BBS FS](https://github.com)（Blockbench Studio for Minecraft）的多人协作模组，基于 Minecraft 1.20.1 Fabric。它让多名玩家在同一个 BBS 影片项目中实时协作编辑，同步光标、选中、关键帧、回放，并支持资产和影片数据的服务器端分发。

- **模组 ID**：`bbs_together`（历史沿用，未改动）
- **当前版本**：1.7.9
- **Minecraft**：1.20.1
- **前置**：BBS FS >= 2.6、Fabric API、Fabric Loader >= 0.15.6
- **Java**：17（编译目标）/ 21（运行 Gradle 9.2）
- **许可**：MIT

---

## 功能介绍

### 实时协作
- **玩家颜色标识**：每名玩家自动分配一个颜色，在 BBS 界面中以彩色高亮显示其选中内容与光标位置。
- **共享光标**：其他玩家的鼠标光标在当前编辑界面实时可见。
- **选中同步**：表单、关键帧、回放片段的选中状态会广播给所有在线玩家。
- **表单锁定**：一名玩家编辑某条回放的表单时，其他玩家看到锁定状态，避免冲突。
- **回放交换**：玩家之间可以交换回放片段的顺序。

### 影片与回放同步
- **影片选择同步**：谁在编辑哪个影片、停留在哪个影片屏幕，其他玩家可见。
- **影片数据实时同步**：一名玩家保存关键帧/轨道修改后，影片数据自动推送给所有在线玩家，无需手动重传。
- **影片列表/重命名/删除同步**：新增、重命名、删除影片时列表在所有客户端刷新。
- **回放合并**：支持多人录制的回放片段合并到同一时间线。

### 影片提交（版本历史）
- **提交**：在影片编辑页的「提交」页填写提交信息后提交。服务器为该影片记录一份快照与差异，存于影片自己的附属文件夹 `<存档>/bbs/films/<影片目录>/_<影片名>/_together/`（与 BBS 的自动备份同一文件夹，原版 BBS 与不含 Together 的客户端都不会把它当成影片），每部影片最多保留 300 条。提交落在**发起者当前分支**上，按钮显示「提交到 <当前分支>」；不会把本分支内容写进图里选中的其他分支。客户端会把编辑器中尚未保存的影片数据一并发送，刚改完关键帧轨道不保存直接提交也能记下改动。提交没有产生新记录时（与分支最新提交内容相同，或影片数据读写失败）服务器回传原因并弹窗提示。
- **提交图**：横轴按影片分列，节点为提交、连线为父子关系，连线恒为暗灰色。默认分支固定在泳道带中央，其他分支从左右两侧交替展开，减少交叉。纵轴按时间自上而下排列，最旧在上、最新在下，视图默认吸附最新提交，翻看历史后滚回底部会重新吸附。影片当前分支线上的提交为实心并带高亮描边；其余（退回时保留的提交、影片未停留的分支）为空心灰字。未单独设色的提交（包括新建分支上的提交）默认使用界面主题色；手动设色或显式重置为灰色仍以服务器保存的颜色为准。当前提交所在行常驻淡主题色底与左侧色条，即使选中其他提交也能看出影片停在哪里。行样式、滚动条与滚轮行为与 BBS 列表一致。
- **他人选中提交**：选中提交会同步给同一影片的其他玩家，行尾显示其头像（回放列表样式：10px 面部 + 1px 玩家色描边，最多 4 个，从右往左并排，自己的头像排最前）；文本和分支标签会为头像让出宽度，不会被遮挡；离开影片或断开时头像消失。提交图因数据刷新、他人提交或提交详情响应而重建时，自己的选中按影片 + 提交 id 恢复，不再跳回最新提交。
- **当前提交位置**：每名玩家所在分支的头部提交常驻显示头像，不随选中/取消选中消失；自己和别人的当前位置都能看到。头像采用回放列表样式：10px 面部 + 1px 不透明玩家色描边。
- **提交详情**：按 BBS 属性面板样式逐行列出提交 id、类型、分支、作者、时间，以及剪辑与关键帧的增删改统计和各段差异，内容多时可滚动。未选中提交时，此处改为显示编辑器影片相对当前分支头的未提交改动；仅在编辑内容实际变化时重建（最多每秒一次），避免大影片反复全量比较导致卡顿。影片未在编辑器中打开时会提示先打开。
- **退回与合并**：右键**当前分支**的提交可选择「撤回至此提交」，弹窗提供「删除并退回」与「保留并退回」：前者删除该提交之后的提交，后者将这些提交保留在历史中；两种方式都以选中的提交为退回点。不同分支的提交不显示退回入口。另提供「合并到此提交」：把该提交至当前分支头之间的提交压缩为一个节点，影片内容保留当前分支头，适用于整理连续的小提交。压缩会重写这段历史，若区间被其他分支引用则拒绝执行并提示。
- **提交重命名**：右键任意提交节点选择「重命名提交」，仅修改提交信息，不影响提交 id、父子关系或分支头。
- **分支**：右键节点「从此处新建分支」；页签顶部显示当前分支；右键任意提交可直接「检出此提交所在分支」，也可在底部输入分支名检出。切换只把**该玩家**的影片内容切到目标分支头部，其他玩家留在各自分支。每名玩家在当前影片上的分支由服务器持久化，重进或重启后仍在原分支。
- **多人分支隔离**：每个分支使用独立工作副本（`_<影片名>/_together/w/<分支哈希>.bin`），同分支实时共享，不同分支互不覆盖。提交只落在发起者当前分支；主影片 `<影片名>.dat` 始终跟随默认分支，分支数据随影片目录移动且不进入原版影片列表。
- **标签页与打开速度**：同一影片仅保留一个页签，从影片列表再次打开时切换到已有页签；「影片节点」固定在最左侧。打开影片时服务端直接返回玩家所在分支，后续请求仅刷新分支名与提交图；最近打开的影片在客户端缓存，以便快速重开。
- **编辑页内的提交页**：影片编辑页「Properties」组新增「提交」小页签，包含提交图、提交详情（或未提交改动）、提交信息与操作按钮。详情栏整条顶边可拖动，中央显示短线手柄，双击恢复默认高度，高度记入编辑器布局设置。「提交」dock 页首次默认与属性页合并，解锁布局后可拖动、调整大小或更换栏位。
- **单个提交颜色**：右键提交节点选择「提交颜色」，用 BBS 调色盘取色。颜色由服务器随提交保存并广播，所有玩家看到同一套颜色，重启后仍然保留；旧版本留在本机 `config/bbs_together_commit_colors.json` 的颜色会在首次打开提交图时自动补传到服务器（需具备影片编辑权限）。
- **服务端权威**：提交、退回、压缩与分支操作均由服务器落盘后广播，所有客户端同步刷新；切分支只修改发起者自己的玩家分支并只回传该分支内容。

### 录制同步
- **一键录制开关**：服务器管理员可通过命令同时控制多名玩家开始/停止录制。
- **主录制协调**：指定一名"主录制"玩家，其时间线作为基准，其他玩家的录制片段在主录制结束后自动对齐合并。

### 合作录制
- **发起请求**：影片编辑页「录制回放」按钮右键 →「请求合作录制」，弹窗多选当前在线玩家（头像 + 名字）后发出邀请。名单直接读取原版在线玩家列表，不依赖行为日志缓存，因此刚加入的玩家也会立即出现；BBS 等级 1（编辑者）与等级 2（管理员）均可发起邀请，域白名单只限制可编辑内容，不影响邀请入口。
- **邀请前自动提交**：点击「发送邀请」时，若当前影片有未提交改动（包括新增回放等结构性改动），客户端会先把编辑器中的实时影片提交到当前分支，再发出邀请。这样服务器校验回放数量时使用的是最新数据，而不是旧的工作副本。
- **置顶邀请弹窗**：被邀请玩家在右上角收到置顶请求（任何界面可见，包括不在 BBS 界面时），显示发起者、影片名、可同意剩余时间的倒计时条；快捷键「同意 / 取消」可在 BBS 设置的「影片控制器」分类中改键。
- **选回放房间**：同意后双方进入房间——左侧为影片全部回放（方框 + 小字名称），右侧为成员列表（灰色 = 未选择、绿色 = 已选择，发起者带 ★）；房间内实时显示各成员鼠标位置；点击回放认领（框上显示认领者头像并锁定），右键自己的认领取消。
- **协同录制**：全员认领后发起者点「开始录制」，服务器同时拉起所有成员的录制（各自录入自己认领的回放，可中途停止）；全员交卷后服务器合并进影片并广播。被邀请玩家若处于其他分支，同意邀请时会先自动提交其当前分支，再切换到发起者所在分支；切换失败则无法加入会话并收到提示。
- **服务器权威**：会话期间与合并后 30 秒内锁定该影片的客户端写入（全量/逐通道同步被拒），杜绝成员本地旧状态覆盖合并结果；一玩家同时只能在一个会话，一部影片同时只允许一个会话。
- **审计**：合并完成在行为列表记录一条合作录制条目（发起者、成员与各自认领的回放）。
- **邀请时限**：`bbs_together.config.coop.coop_invite_seconds`（默认 60 秒，范围 10–600）。

### 资产同步
- **资产清单（Manifest）**：玩家进入服务器时，服务器把 `config/bbs/assets/` 下所有资产（纹理、模型、音频、粒子等）的 SHA-1 与文件大小清单发给客户端。
- **自动下载**：客户端发现本地缺失或不一致的资产时，自动从服务器请求下载。
- **自动上传**：客户端本地新增或修改的资产自动上传到服务器，服务器落盘到 `config/bbs/assets/`。上传携带“上次看到的服务器 mtime”作为 CAS 令牌：服务器文件已被他人改写时拒绝覆盖并回推 manifest，旧客户端/旧服务端仍按原协议兼容。
- **大小保护**：客户端可在 F6 面板设置单文件大小上限（默认 1024 MB，范围 16 MB–2 GB），超过上限的文件自动跳过不下载/上传。
- **超限模型标记**：总大小超过上限的模型文件夹仅下载 `config.json` 占位，在模型列表中标记为红色"模型过大"。
- **手动同步按钮**：F6 实用工具面板提供"下载全部模型"和"上传全部模型"按钮，点击后请求服务端重发清单，仅同步差异文件（不强制全量重传）。
- **上传节流**：文件逐个发送，间隔 200ms，避免 crusher 分片洪水导致断连。
- **传输压缩**：影片工作区等大体积载荷在分片发送前先经 GZIP 压缩，小体积包保持原样，显著降低协作时的带宽占用。

### 关键帧默认样式
- 可在 BBS 设置中为新建关键帧指定默认颜色、形状、插值方式，统一协作时的关键帧风格。

### 服务器行为列表
- **审计日志面板**：底部导航栏新增面板，记录玩家在服务器上的编辑 / 下载 / 上传历史，存档持久化到 `<存档>/bbs/behaviors/`。
- **内容对比记录**：模型保存、影片保存、资产上传都会先与上次状态做内容对比，未实际改动不产生记录；上传自动聚合为模型，皮肤与压缩包不记录，并统计传输大小。
- **三栏布局**：左侧玩家列表（仅 OP 可见，非 OP 显示"没有权限"）、中间行为列表（类型图标 + 描述 + 时间，新的在底部）、右侧详情（时间 / 玩家 / 大小 / 剪辑等）。
- **点击跳转**：详情中的模型条目可跳转到 morph 面板并选中该模型；影片条目可跳转到影片面板并选中对应剪辑。
- **OP 管理**：右键玩家可设为 / 解除 OP（带确认与服务器日志），可移除该玩家的全部日志（二级确认）。
- **隐私保护**：非 OP 玩家可见行为内容但所有头像与名称完全匿名，由服务端剥离身份数据。
- **日志容量**：`bbs_together.config.behaviors.behavior_log_limit`（默认 1000，范围 100–50000），超出后自动淘汰最旧条目。

### 模型删除请求
- **请求服务器删除**：模型列表右键任意模型 →「请求服务器删除」，确认后在服务器行为列表生成一条待审批请求。
- **审批闭环**：管理端（原版 OP 或 BBS 2 级）在行为列表右键该请求即可「同意 / 拒绝」；同意后服务器删除该模型资产并广播所有客户端删除本地拷贝；拒绝后条目灰渐变标注红叉与「已拒绝」。等待审批的条目灰字标注，详情页显示审批状态与审批人。
- **防复活 tombstone**：模型从服务器删除后，tombstone 持久化保存，离线客户端再次重传该模型会被服务器丢弃，重启或长时间离线也不会把模型“复活”。
- **仅本地删除**：右键 →「仅本地删除」只删本机拷贝；开启自动同步时确认菜单直接提供「关闭自动同步并删除 / 仍要仅删除 / 取消」，避免模型被重新同步回来。
- **只读可见**：0 级只读玩家的模型右键菜单只显示这两个删除项（请求需管理端审批，本地删除只动本机文件），其余编辑操作照旧全部锁定。

### 撤回撤销防误撤
- 远端同步数据落盘前先封存玩家进行中的撤销批次，保证撤销条目的"改后快照"只含玩家自己的修改。
- 撤销同步到服务器时按路径携带期望基线（`s_undo_sync`）做校验，他人已改过的内容会被拒绝并回推服务器现状（`c_undo_rejected`），杜绝"Ctrl+Z 一键回滚他人修改"。

### BBS 权限等级（bbsop）
- **三级权限**：0 级仅浏览（可浏览、可下载，不可编辑、不可上传）、1 级编辑者（默认可编辑全部内容）、2 级管理员（可编辑全部内容并管理他人权限）。除服主外，玩家进服默认 0 级。
- **服主默认 2 级**：单人 / LAN 存档由集成服务器按主机 GameProfile 识别开服者，首次进服自动获得 2 级。专用服不再把「第一个进服的玩家」当作服主；首次开服请由控制台执行 `/bbsop <玩家> 2` 显式授予管理员，避免陌生人抢到首个管理员位。
- **功能域**：伪装、影片、模型方块、粒子、模型编辑器、纹理、音频编辑器、资产上传八个域。伪装/影片/模型方块/上传有独立服务端写包；粒子、模型编辑器、纹理、音频的资产上传按路径映射到对应域（`particles/`、`models/`、`textures/`、`audio/`），客户端 UI 与服务端上传权限双重判定。
- **录制子权限**：影片域下的隐藏子域「录制」，控制回放录制（录制按钮、录制快捷键、`/bbstogether record` 远程触发）与影片预览的「录制视频/截图」按钮。它不占「修改可编辑行为」菜单的顶层项——鼠标悬停「影片」行时在右侧弹出「录制：允许/禁止」小按钮切换；服务端在录制数据包与动作录制两条通道复核。
- **1 级域白名单**：管理员可对 1 级玩家逐域"允许/禁止"；首次禁止即进入白名单模式（其余全开），空白名单 = 全部禁止。
- **管理入口**：服务器行为面板玩家列表——拖拽玩家到目标等级分组即可换级；右键「修改 BBS 等级」「修改可编辑行为」子菜单。仅 2 级玩家可管理（原版 OP 走 `/bbsop` 指令）；管理员不可拖动修改自身等级、不可解除自身 OP。
- **等级分组**：玩家列表按 2 → 1 → 0 三级分组显示，等级持久化到 `<存档>/bbs/bbsop.json`，玩家每次进服自动归入原分组；点选分组标题可按组过滤行为列表。
- **服务端权威**：上传、影片写入、模型方块、远端录制等所有写通道在服务端按域复核，改客户端也无法绕过；0 级玩家进入 BBS 各编辑页呈只读态（灰罩 + 锁图标 + 仅浏览）。
- **即时生效**：等级 / 域变更后服务端立即推送，目标玩家 UI 无需重进即切换锁定状态。

### 资产锁定（BBS 等级 2）
- **入口**：伪装模型右键菜单「锁定模型...」、影片列表右键菜单中的锁按钮、模型方块面板「看向目标」下方的「锁定编辑」开关。
- **规则**：支持禁止所有人编辑、仅白名单玩家可编辑、仅黑名单玩家不可编辑三种模式。只有 BBS 等级 2 玩家始终可编辑；锁的创建者被降级后同样受锁限制。
- **名单**：白名单与黑名单使用头像多选面板；两种模式的入口始终显示，切换模式不会丢弃另一份名单。
- **显示与保护**：锁定标记按玩家区分——无法编辑该资产的玩家看到锁定模型灰色遮罩与「已锁定」、锁定影片在列表名称后的闭合锁头、锁定模型方块在 F3 描边中的锁图标；锁的创建者在可编辑时，模型格右下角显示小锁头、影片列表显示打开的锁头；其他可编辑玩家看不到锁定标记，等级 2 管理员保留管理用标记（模型格/影片列表的打开锁头与模型方块 F3 锁图标）。锁定模型与影片呈只读，锁定模型方块不可破坏、不可复制属性，也不能被不能编辑它的玩家右键打开。
- **服务端校验与持久化**：模型上传、影片写入、模型方块写入与破坏均在服务端复核。锁保存于 `<存档>/bbs/asset_locks.json`（UTF-8 + 临时文件原子替换），影片或模型改名、删除时同步迁移或清理。模型删除 tombstone 持久化到 `<存档>/bbs/asset_tombstones.json`，重启或超过 30 分钟也不会被离线客户端的自动同步复活。

### 服务器命令
- `/bbstogether record <玩家>`：切换指定玩家的录制状态；若其中有人正在录制，则停止所有目标玩家的录制。
- `/bbstogether restore <模型>`：清除该模型的持久删除 tombstone，允许再次上传；不会恢复已删除的文件。需要 OP 或 BBS 等级 2。
- `/bbstogether diag`：输出当前资产同步/队列诊断信息。
- `/bbsop <玩家> [0-2]`：查询或设置玩家的 BBS 权限等级（0 仅浏览 / 1 编辑者 / 2 管理员）。仅服主（原版 2 级 OP 以上）、服务器控制台或 BBS 等级 2 的玩家可用。
- `/bbsop <玩家> grant <域> <allow|deny>`：允许或禁止 1 级玩家的某个功能域；`/bbsop <玩家> grant reset` 恢复为不受限。域：morph、film、record、model_blocks、particles、model_editor、textures、audio、upload。

## 使用教程

### 安装
1. 安装 [Minecraft 1.20.1](https://www.minecraft.net/) 与 [Fabric Loader](https://fabricmc.net/use/)。
2. 把以下 jar 放入 `mods/` 文件夹：
   - Fabric API
   - BBS FS >= 2.6
   - `together-link-1.7.9-1.20.1.jar`
3. 服务端与所有客户端都需要安装相同版本的 BBS FS 与 Together Link。

### 开启多人协作
1. 启动服务端，玩家正常加入世界。
2. 任意玩家按 BBS 快捷键打开 BBS 仪表盘，新建或打开一个影片。
3. 其他玩家加入同一影片后，即可看到彼此的光标、选中颜色与实时修改。
4. 服务器管理员输入 `/bbstogether record @a` 可让所有人开始/停止录制。

### 配置
在游戏内打开 BBS 设置（Mods 列表 → Together Link → Config），可调整：

| 配置项 | 说明 |
|--------|------|
| CDN 地址 / 访问令牌 | 可选的只读 CDN 下载源：填地址后优先从 CDN 拉取清单中的资产，SHA-1/大小校验失败自动回退服务器；上传始终走服务器 |
| 启用下载 | 开启后从服务器自动下载缺失资产 |
| 启用上传 | 开启后把本地资产上传到服务器 |
| 接收推送 | 开启后接收服务器推送的资产更新 |
| 关键帧默认颜色/形状/插值 | 新建关键帧的默认样式 |

配置文件位于 `config/bbs_together.json`。

### 资产目录
- 服务器权威资产目录：`<服务器目录>/config/bbs/assets/`
- 玩家资产会自动同步到此目录，服务器重启后不丢失。

## 影片提交模块（实现说明）

### 服务端
- `src/main/java/mchorse/bbs_together/commits/FilmCommit.java`：一条提交（id、父提交、分支、信息、作者、时间、类型、颜色）。
- `src/main/java/mchorse/bbs_together/commits/FilmFolders.java`：统一计算每部影片的附属文件夹 `<影片目录>/_<影片名>/_together/`，并负责旧版 `<存档>/bbs/films/_commits/<影片>/` 的迁移、移动与清理。附属文件夹以 `_` 开头，BBS 的影片扫描会跳过它，原版只看到 `<影片名>.dat`。
- `src/main/java/mchorse/bbs_together/commits/FilmCommitStore.java`：磁盘存档与提交图操作。`index.bin` 记分支、提交列表与各提交颜色，`s/` 存快照、`d/` 存差异；提供 `commit`、`list`、`diff`、`rollback`（退回保留/删除）、`squash`（压缩到指定提交）、`createBranch`、`rename`、`setColor`。提交时复用分支头快照缓存，避免同一次提交重复读取并解析整部影片。
- `src/main/java/mchorse/bbs_together/commits/FilmBranchStore.java`：每分支工作副本与玩家分支选择。`w/<分支哈希>.bin` 存该分支的未提交影片，`players.bin` 记每名玩家在此影片上的分支；默认分支与主影片文件 `<影片>.dat` 保持同步，其他分支不写主文件。主文件读取改为直接复用已解析的 `Film`，未变化的保存会跳过重复写盘与 BBS 备份。
- `src/main/java/mchorse/bbs_together/commits/FilmDiffBuilder.java`：按剪辑、关键帧、字段生成提交差异与统计，客户端复用同一份实现计算未提交改动。
- `TogetherServerNetwork.java` 的提交处理器：校验权限、参数与影片锁，按玩家所在分支落盘后广播 `c_commits` / `c_commit_added` / `c_commit_index` / `c_commit_color` / `c_commit_rejected`，并写入行为日志。影片数据同步、保存和撤销也按分支过滤与落盘。

### 协议（`bbs_together` 命名空间）
`c/s_commit_index`、`c/s_commits`、`c/s_commit_diff`、`c/s_commit_head`、`c/s_commit_create`、`c/s_commit_rename`、`c/s_commit_color`、`s_commit_selection`、`c_commit_selections`、`c_player_commit_positions`、`c_film_branch_state`、`c_film_branch`（只带影片与分支名，用于整部影片已先行送达时校准分支）、`c/s_commit_revert`（带 mode 字节）、`s_commit_squash`、`s_branch_create`、`s_branch_checkout`、`c_commit_added`、`c_commit_renamed`、`c_commit_color`、`c_commit_rejected`（带原因字节）。

分支隔离附加字段：`c_film_saved_sync` 与 `c_film_data_sync` 带 `branch`，客户端丢弃非当前分支的包；`c_commits` 带收件人的当前分支，用于覆盖图里的 `current`；`s_branch_checkout` 只切换发起者自己的分支并只向他回传该分支的完整影片。

### 客户端
- `network/TogetherClientNetwork.java`：发送与接收上述包。
- `ui/commits/FilmCommitClient.java`：客户端缓存（索引、各影片提交图、提交差异、分支头快照），`version()` 变一次刷新一次界面。
- `ui/commits/CommitUi.java`：入口（打开「影片节点」页签、顶栏图标、编辑页提交页）、退回/压缩确认与提交被拒提示；提交图只允许操作当前分支上的提交。
- `ui/commits/UICommitsPanel.java`：「影片节点」页本身——左侧有提交的影片列表，右侧提交图，底部选中提交的详情。
- `ui/commits/UIFilmCommitsView.java`：嵌在影片编辑页「Properties」组里的「提交」页，提交图、详情（含未提交改动）与操作按钮栏。
- `ui/commits/UICommitGraph.java`：提交图绘制、命中检测、右键菜单、右键取色；默认分支固定在中线，其他分支左右交替展开。
- `ui/commits/UICommitActions.java`：底部按钮栏（提交、新建分支、切换分支、退回）。
- `ui/commits/UICommitInfo.java`：选中提交的详情、未提交改动、重命名与差异展示；未提交改动按编辑版本重建，避免空闲时反复计算。
- `ui/commits/UICommitRollbackOverlay.java`：退回确认弹窗，提供「删除并退回」与「保留并退回」。
- `ui/commits/CommitColors.java`：旧版本保存在 `config/bbs_together_commit_colors.json` 的本地颜色，作为服务器颜色未知时的回退；服务器颜色变化会镜像回该文件，旧颜色首次同步时补传。

### 提交页相关注入
- `mixin/UIFilmPanelCommitsMixin.java`：在影片编辑页挂上「提交」dock 页、顶栏图标和「影片节点」页签内容；「提交」首次并入属性页栈，后续遵循用户布局；「影片节点」固定在页签条最左侧。
- `mixin/UIPanelTopBarCommitsMixin.java`：页签条为顶栏图标让出位置。
- `mixin/UIDataDashboardPanelCommitsMixin.java`：让影片编辑页的 `showTab` / `getOpenId` / `saveOpen` 认这个伪数据 id。
- `mixin/UITabListCommitsMixin.java`：伪数据 id 的页签文字；同一影片只复用一个页签；打开影片时若「影片节点」页签处于激活状态则另开页签而不是替换它。
- `mixin/FilmRepositoryMixin.java`：客户端影片缓存命中时立即打开编辑器，随后仍由服务器分支状态包校准。
- `mixin/FilmLoadQuietMixin.java`（服务端）：把管理器 LOAD/SAVE 按玩家所在分支落盘，避免重复传输整部影片，并防止编辑侧分支覆盖默认分支主文件。
- 每秒活动时间过滤集中在 `TogetherEditSyncQueue.add`，未为此新增注入。
- 其他注入收在 `src/client/resources/bbs-together.client.mixins.json` 与 `src/main/resources/bbs-together.mixins.json` 的列表中，属于此前已有的 BBS 兼容层。

- 新增合作录制：右键「录制回放」按钮邀请玩家，对方通过右上角置顶弹窗（快捷键可在 BBS 设置的「影片控制器」分类修改）同意后进入选回放房间；全员认领回放后由发起者开始录制，各成员可中途停止，全员交卷后服务器自动合并并广播
- 新增模型删除请求：模型右键「请求服务器删除」，管理员在行为列表审批；删除后由持久 tombstone 阻止自动同步把模型传回来；另提供「仅本地删除」
- 新增录制子权限：影片域下新增「录制」子域，控制回放录制与「录制视频/截图」按钮
- 新增撤销保护：撤销会被服务器校验，他人已修改过的内容不再被一键回滚
- 优化资产同步：清单携带修改时间并自动仲裁冲突，上传使用服务器 mtime 作为 CAS 令牌，两端不再互传同一文件
- CDN 设置接入只读下载路径：优先从配置的 CDN 地址获取资产，校验 SHA-1/大小后落盘，失败自动回退服务器；上传和权限校验仍由服务器负责
- 服务端把 `asset_sync_max_mb` / `coop_invite_seconds` 随 hello 下发给客户端，下载上限不再依赖两端各自配置
- 服务端 manifest/请求/库存处理改用有界共享 I/O 线程池，上传分片改为单线程有序写入（不再占用服务器 tick 线程），客户端 SHA-1 缓存与删除 tombstone 加上限，避免长时间运行或恶意刷包无限增长
- l10n 只保留 addon 事件这一处链接注册，去掉重复 registerOne，减少启动时重复加载语言文件
- 文件夹改名/删除现在同步迁移或清理分支/提交数据，以及玩家提交选择、正在编辑/屏幕状态、光标、表单锁和延迟保存任务
- 新增 `/bbstogether restore <模型>`：清除持久删除 tombstone，允许重新上传被删除的模型
- 资产同步提示改为左下角极简状态组件：活动时仅显示图标、2px 进度线和百分比，完成时播放对勾脉冲，空闲时只显示状态点；绘制在所有栏/菜单之上，但不拦截点击，不影响编辑
- manifest resync 与行为上报增加每玩家限流，等级 1 客户端不能刷爆行为日志
- 修复：点选等级分组标题过滤行为列表时崩溃
- 注意：客户端与服务端必须使用相同版本；白名单模式下的 1 级玩家升级后默认禁止录制，需管理员执行 `grant record allow`
